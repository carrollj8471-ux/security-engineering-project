# T1547.001 Registry Run Keys / Startup Folder Detection Lab

> **Implementation note:** The initial standalone `100140`/`100141` design did not generate the expected alert. The validated implementation extends built-in Wazuh rule `92300` with custom rule `100141`. The troubleshooting sequence and observed evidence are documented in `README.md`.

## Portfolio objective

Validate that Sysmon and Wazuh can collect a Windows Registry Run-key modification, distinguish telemetry collection from alert generation, and generate a higher-severity alert mapped to MITRE ATT&CK `T1547.001` when a Run value launches a command or script interpreter.

## MITRE ATT&CK mapping

| Field | Value |
|---|---|
| Technique | `T1547.001 – Registry Run Keys / Startup Folder` |
| Tactics | Persistence, Privilege Escalation |
| Platform | Windows |
| Primary telemetry | Sysmon Event ID `13` – Registry value set |
| Observed behavior | A value was added beneath `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Detection condition | Built-in Run-key rule `92300` plus an interpreter executable in `win.eventdata.details` |

Run keys are legitimate Windows extensibility mechanisms. A match is an investigation signal, not proof of malicious persistence.

## Lab environment

| Component | Observed value |
|---|---|
| Endpoint | `WIN11.corp.local` |

## Safety boundaries

- Use only the local `HKCU` Run key on the lab endpoint.
- Use benign text-marker commands only.
- Do not log off or reboot while a test value exists.
- Remove every Run value immediately after its telemetry is collected.
- Verify that no marker executed during the lab.
- Use `notepad.exe` as the benign non-interpreter control.

## Detection hypothesis

If a value is added beneath the current user's Run key, Sysmon should record Event ID `13`. Wazuh should collect the event. Built-in rule `92300` should establish the Run-key context, and custom rule `100141` should elevate the event when the stored data references a command or script interpreter.

## Phase 1: Verify readiness and establish a baseline

Run in Administrator PowerShell on `WIN11`:

```powershell
Get-Date -Format o

Get-Service Sysmon, Sysmon64, WazuhSvc -ErrorAction SilentlyContinue |
    Select-Object Name, Status, StartType

Get-WinEvent -FilterHashtable @{
    LogName = "Microsoft-Windows-Sysmon/Operational"
    Id      = 12, 13, 14
} -MaxEvents 10 -ErrorAction SilentlyContinue |
    Select-Object TimeCreated, Id, ProviderName

$RunKey = "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
$ValueName = "T1547.001-Benign-Lab"

Get-ItemProperty -Path $RunKey -Name $ValueName -ErrorAction SilentlyContinue
Get-Date -Format o
```

Expected: Sysmon and Wazuh are running, recent registry telemetry exists, and the benign value is absent.

## Phase 2: Create the benign Run value

```powershell
$Start = Get-Date
$RunKey = "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
$ValueName = "T1547.001-Benign-Lab"
$Marker = "C:\ProgramData\T1547.001-run-key-marker.txt"
$Command = "C:\Windows\System32\cmd.exe /c echo Benign T1547.001 validation > $Marker"

New-ItemProperty `
    -Path $RunKey `
    -Name $ValueName `
    -Value $Command `
    -PropertyType String `
    -Force

Get-ItemPropertyValue -Path $RunKey -Name $ValueName
Test-Path $Marker
Get-Date -Format o
```

Expected: the value contains the intended command and `Test-Path` returns `False`. Do not log off or reboot.

## Phase 3: Confirm local Sysmon telemetry

```powershell
$RegistryEvent = Get-WinEvent -FilterHashtable @{
    LogName   = "Microsoft-Windows-Sysmon/Operational"
    Id        = 13
    StartTime = $Start
} | Where-Object {
    $_.Message -match [regex]::Escape($ValueName)
} | Select-Object -First 1

$RegistryEvent | Format-List TimeCreated, Id, RecordId, ProviderName, Message
Test-Path $Marker
```

Record the event type, target object, details, modifying image, user, process GUID, timestamp, and record ID. The observed Sysmon `RuleName` may contain the deprecated label `T1060`; map the case study to the current technique `T1547.001`.

## Phase 4: Hunt in Wazuh before adding rules

Run progressively:

```text
agent.name:"WIN11" AND data.win.system.eventID:"13"
```

```text
agent.name:"WIN11" AND data.win.system.eventID:"13" AND data.win.eventdata.targetObject:*T1547.001-Benign-Lab*
```

```text
agent.name:"WIN11" AND data.win.system.eventID:"13" AND data.win.eventdata.details:*T1547.001-run-key-marker*
```

If the alert view returns nothing, compare manager archives and alerts:

```bash
sudo grep -F '"eventID":"13"' /var/ossec/logs/archives/archives.json |
grep -F 'T1547.001-Benign-Lab' | tail -1

sudo grep -F '"eventID":"13"' /var/ossec/logs/alerts/alerts.json |
grep -F 'T1547.001-Benign-Lab' | tail -1
```

Archive output with no alert output proves collection succeeded while dedicated detection did not.

## Phase 5: Remove the initial value

```powershell
Remove-ItemProperty -Path $RunKey -Name $ValueName -Force
Test-Path $Marker
```

## Phase 6: Inspect the built-in Sysmon rule path

On the Wazuh manager:

```bash
sudo grep -R -n -B 5 -A 15 '<rule id="61615"' /var/ossec/ruleset/rules
sudo grep -R -n -B 5 -A 20 '<rule id="92300"' /var/ossec/ruleset/rules
```

The validated hierarchy was:

```text
61615 — Sysmon Event ID 13
└── group sysmon_event_13
    └── 92300 — Registry Run/RunOnce path (level 0)
        └── 100141 — interpreter stored in value data (custom level 8)
```

## Phase 7: Install the final custom rule

Confirm the ID is available and back up the local rules:

```bash
sudo grep -R -n --include='*.xml' 'id="100141"' \
  /var/ossec/etc/rules /var/ossec/ruleset/rules

sudo cp /var/ossec/etc/rules/local_rules.xml \
  /var/ossec/etc/rules/local_rules.xml.bak-$(date +%Y%m%d-%H%M%S)

sudo nano /var/ossec/etc/rules/local_rules.xml
```

Add:

```xml
<group name="windows,sysmon,registry,persistence,mitre,">
  <rule id="100141" level="8">
    <if_sid>92300</if_sid>
    <field name="win.eventdata.details"
           type="pcre2">(?i)(cmd|powershell|pwsh|wscript|cscript|mshta|rundll32|regsvr32)\.exe</field>
    <description>Registry Run key configured to launch a command or script interpreter</description>
    <mitre>
      <id>T1547.001</id>
    </mitre>
  </rule>
</group>
```

Validate and activate:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
sudo systemctl restart wazuh-manager
sudo systemctl is-active wazuh-manager
```

## Phase 8: Positive validation

Generate a fresh value after the restart:

```powershell
$RunKey = "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
$ValidationName = "T1547.001-Validation-03"
$ValidationMarker = "C:\ProgramData\T1547.001-validation-03.txt"
$ValidationCommand = "C:\Windows\System32\cmd.exe /c echo Benign T1547.001 validation 03 > $ValidationMarker"

New-ItemProperty `
    -Path $RunKey `
    -Name $ValidationName `
    -Value $ValidationCommand `
    -PropertyType String `
    -Force

Get-ItemPropertyValue -Path $RunKey -Name $ValidationName
Test-Path $ValidationMarker
```

Search:

```text
agent.name:"WIN11" AND rule.id:"100141"
```

Verify rule `100141`, level `8`, Sysmon Event ID `13`, the Run-key target, interpreter command, and MITRE ID `T1547.001`.

## Phase 9: Negative control

Remove the positive value, then create a direct native-executable value:

```powershell
Remove-ItemProperty -Path $RunKey -Name "T1547.001-Validation-03" -Force

$ControlName = "T1547.001-Benign-Control"
$ControlCommand = "C:\Windows\System32\notepad.exe"

New-ItemProperty `
    -Path $RunKey `
    -Name $ControlName `
    -Value $ControlCommand `
    -PropertyType String `
    -Force
```

Confirm collection in `archives.json`, then search:

```text
agent.name:"WIN11" AND rule.id:"100141" AND data.win.eventdata.targetObject:*T1547.001-Benign-Control*
```

Expected: the Event ID `13` exists in the archive, while the elevated-rule query returns no results.

## Phase 10: Cleanup

Remove all exact test values and marker paths, then verify each is absent. Do not use broad registry deletion commands.

```powershell
$RunKey = "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
$ValueNames = @(
    "T1547.001-Benign-Lab",
    "T1547.001-Validation",
    "T1547.001-Validation-02",
    "T1547.001-Validation-03",
    "T1547.001-Benign-Control"
)

$ValueNames | ForEach-Object {
    Remove-ItemProperty -Path $RunKey -Name $_ -ErrorAction SilentlyContinue
}

$RunProperties = Get-ItemProperty -Path $RunKey
$ValueNames | ForEach-Object {
    [PSCustomObject]@{
        ValueName = $_
        Exists = $_ -in $RunProperties.PSObject.Properties.Name
    }
}
```

All `Exists` values must be `False`.
