# T1562.001 Impair Defenses Detection Lab

## Safety boundary

- Use only the isolated WIN11 VM and an empty `C:\ProgramData\T1562-Portfolio-Lab` directory.
- Do not disable real-time protection, stop security services, disable logging, or place files in the excluded directory.
- Remove the exclusion in a `finally` block and verify the final state.

## Readiness

Confirm Defender antivirus, real-time protection, behavior monitoring, `WinDefend`, `Sysmon`, and `WazuhSvc` are active. Confirm the lab path is neither present nor excluded.

## Positive test

Create the empty directory and launch a child PowerShell process whose script adds the exact path, waits three seconds, and removes it in `finally`. Capture Sysmon Event `1` and Defender Event `5007` from the test start time.

Expected: the exclusion is briefly observed, then absent; real-time protection remains enabled.

## Wazuh validation

```text
agent.name:"WIN11" AND rule.id:"100213" AND data.win.system.eventRecordID:"25375"
```

Expected: level `12`, T1562.001.

## Negative control

Launch a child PowerShell process that runs only `Get-MpComputerStatus`. Confirm its Sysmon record reaches Wazuh under ordinary PowerShell classification and is absent from rule `100213`.

## Cleanup

Idempotently remove the exclusion and lab directory. Confirm Defender protections remain enabled and `WinDefend`, `Sysmon`, and `WazuhSvc` remain running.

## Troubleshooting

- Use a child process so Sysmon Event `1` retains the full command line.
- Correlate Event `1` command intent with Defender Event `5007` state-change evidence.
- Verify manager ingestion separately from rule matching.
- Generate fresh activity after rule deployment; archived events are not reclassified.
- If restoration fails, remove the exclusion immediately before continuing investigation.
