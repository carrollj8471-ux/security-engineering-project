# T1218.011 Rundll32 Detection Lab Runbook

## Purpose

Validate endpoint telemetry, Wazuh collection, and ATT&CK-mapped detection for Rundll32 proxy execution without installing software or using a malicious payload.

## Safety boundaries

- Use only the Windows-supplied `shell32.dll,Control_RunDLL appwiz.cpl` command.
- Do not install or remove software from Programs and Features.
- Close spawned windows after evidence collection.
- Generate fresh events after every Wazuh manager restart.
- Do not edit Wazuh built-in rules under `/var/ossec/ruleset/rules`.

## Phase 1 — Readiness

Run in elevated PowerShell on WIN11:

```powershell
Get-Date -Format o

Get-Service Sysmon, Sysmon64, WazuhSvc -ErrorAction SilentlyContinue |
    Select-Object Name, Status, StartType

$Rundll32 = "$env:WINDIR\System32\rundll32.exe"

Get-Item $Rundll32 |
    Select-Object FullName, Length, CreationTimeUtc, LastWriteTimeUtc

Get-FileHash -Path $Rundll32 -Algorithm SHA256

Get-AuthenticodeSignature $Rundll32 |
    Select-Object Status, StatusMessage,
        @{Name="Signer"; Expression={$_.SignerCertificate.Subject}}

Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 5 |
    Select-Object TimeCreated, Id, ProviderName
```

Pass criteria:

- Sysmon and Wazuh services are running.
- Rundll32 exists in System32.
- Signature status is valid.
- A SHA-256 hash and recent Sysmon events are present.

## Phase 2 — Safe positive simulation

```powershell
$Start = Get-Date
$Rundll32 = "$env:WINDIR\System32\rundll32.exe"
$Arguments = "shell32.dll,Control_RunDLL appwiz.cpl"

$Process = Start-Process `
    -FilePath $Rundll32 `
    -ArgumentList $Arguments `
    -PassThru

$Process | Select-Object Id, ProcessName, StartTime, Path
Get-Date -Format o
```

Expected: Programs and Features opens. Do not change installed software.

## Phase 3 — Local Sysmon validation

```powershell
$RundllEvent = Get-WinEvent -FilterHashtable @{
    LogName   = "Microsoft-Windows-Sysmon/Operational"
    Id        = 1
    StartTime = $Start
} | Where-Object {
    $_.Message -match "rundll32\.exe" -and
    $_.Message -match "Control_RunDLL" -and
    $_.Message -match "appwiz\.cpl"
} | Select-Object -First 1

$RundllEvent | Format-List TimeCreated, Id, RecordId, ProviderName, Message
```

Record the image, command line, parent, process IDs, user, integrity level, hashes, and timestamp.

```bash
sudo jq -rc '
  select(.agent.name == "WIN11") |
  select(.data.win.system.eventID == "1") |
  select((.data.win.eventdata.commandLine // "") | contains("Control_RunDLL")) |

    timestamp,

    parentImage: .data.win.eventdata.parentImage

```

Compare the alerts file without matching the manager's own `sudo` telemetry:

```bash
sudo jq -rc '
```

Observed result: generic rule `100210` won before the specific child was installed.

## Phase 6 — Detection rule

First locate duplicate parents:

```bash
sudo grep -R -n --include='*.xml' 'id="100210"' \
  /var/ossec/etc/rules /var/ossec/ruleset/rules
```

The active first occurrence was in `/var/ossec/etc/rules/mitre_detection_rules.xml`. Place the following rule immediately after that active `100210` definition:

```xml
<rule id="100152" level="12">
  <if_sid>100210</if_sid>
  <field name="win.eventdata.image"
         type="pcre2">(?i)rundll32\.exe$</field>
  <field name="win.eventdata.commandLine"
         type="pcre2">(?i)(Control_RunDLL|,[A-Za-z_][A-Za-z0-9_]*|,#[0-9]+|javascript:|\.cpl(?:\s|$))</field>
  <description>Rundll32 invoked for DLL entry-point or Control Panel proxy execution</description>
  <mitre>
    <id>T1218.011</id>
  </mitre>
  <group>defense_evasion,signed_binary_proxy_execution,rundll32,</group>
</rule>
```

Back up the file before editing:

```bash
sudo cp /var/ossec/etc/rules/mitre_detection_rules.xml \
  /var/ossec/etc/rules/mitre_detection_rules.xml.bak-$(date +%Y%m%d-%H%M%S)
```

Validate before restart:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
```

Do not restart if validation reports that `100210` is unavailable to `100152` or that `100152` will be ignored.

```bash
sudo systemctl restart wazuh-manager
sudo systemctl is-active wazuh-manager
```

Pass criterion: manager returns `active` and validation has no warning involving `100152`.

Repeat the safe simulation after the restart:

```powershell
  -PassThru |
  Select-Object Id, ProcessName, StartTime, Path
```

Search:

```text
agent.name:"WIN11" AND rule.id:"100152"
```

Pass criteria:

- one fresh rule `100152` alert;
- level `12`;
- MITRE ID `T1218.011`;
- command contains `Control_RunDLL appwiz.cpl`;
- parent, user, hashes, and integrity context are retained.

## Phase 8 — Negative control

Run bare Rundll32 without proxy-execution arguments:

```powershell
$ControlStart = Get-Date
Start-Process -FilePath "$env:WINDIR\System32\rundll32.exe" -PassThru |
    Select-Object Id, ProcessName, StartTime, Path
```

Confirm generic observability:

```text
agent.name:"WIN11" AND rule.id:"100210"
```

Confirm no specific alert:

```text
agent.name:"WIN11" AND rule.id:"100152" AND NOT data.win.eventdata.commandLine:*Control_RunDLL*
```

Expected: generic rule `100210` may alert; rule `100152` returns zero hits.

Evidence note: the existing no-result screenshot used retired ID `100151`. Repeat the query above before marking negative validation complete.

## Production recommendations

- Resolve duplicate rule IDs before expanding the custom ruleset.
- Add severity tiers for signed system modules versus unsigned, remote, or user-writable modules.
- Correlate process creation with DLL image-load and network telemetry.
- Baseline common enterprise Rundll32 commands before allowlisting.
- Never suppress all Rundll32 activity based only on the Microsoft signature.
